# 分店營業日報表更新說明

## 上線順序

1. 在 Supabase 備份／匯出 daily_reports，暫停所有裝置的舊版輸入。
2. 在 SQL Editor 執行 supabase_multistore.sql。這是既有表格的更新，不需要重建或刪除原表。
3. 用新版 index.html 替換網站的同名檔案，所有裝置重新整理後再使用。
4. 確認鳳山門市舊資料正常；切換第二間店應是空白。以不同門市同一天各輸入一筆並重新載入，確認資料獨立。

## 新功能與設定

- 門市選單切換鳳山門市／第二間店。11 月開店後直接開始輸入；不限制提前建資料。
- 程式中搜尋 `const STORES`，將 `第二間店` 改成正式店名。只更改 `name`，不要更改 `id`；各裝置使用同一版檔案。
- 全月每日平均＝本店本月日營業額總和／已填日營業額天數。空白不計，0 計入。休店且不希望列入平均時留白。
- 平假日平均、星期分析採相同天數規則。星期圖顯示各星期樣本天數；國定假日依原有外部行事曆，載入失敗時畫面提示暫用週六、日。
- 匯出 CSV 含門市、年月、每日平均和計算天數；列印標題含門市。清空僅作用於所選門市及月份。
- 已輸入資料先同步，再切換門市／月份；儲存失敗保留畫面，阻止切換，按重新整理／載入可重試。未同步時關閉頁面會提示，但沒有離線持久備份。

## 資料庫調整

新增 `store_id`，既有列歸到 `fengshan`，第二店使用 `store2`。保留鳳山店原本的 `id`，新店 ID 加上分店前綴。新增 `(store_id, year, month, date)` 唯一索引，查詢、寫入與清空都包含分店。`updated_at` 改由資料庫更新觸發器管理。

平均值即時計算，不需另存欄位，避免總額修改後平均未更新。

舊版把空白日營業額也存成 0，因此無法自動區分真正的零營業額和未填。更新後請檢查既有 0 元日期；若不該列入平均，將該日營業額清空即可。SQL 不會擅自修改舊金額。

## 現有權限與限制

原有 `Allow public read and write` 政策的 `using (true) with check (true)` 允許匿名讀取及修改／刪除資料；前端分店選單只做資料分類，不是權限控管。這次為相容原有免登入流程，沒有改動 RLS。若要只讓員工使用，應另外加入 Supabase Auth 與門市成員表，依 `auth.uid()` 和 `store_id` 限制存取，再移除公開政策；不能只把條件改成登入身分而不改網站登入流程。

同一天若多個裝置同時編輯，仍採最後寫入整列覆蓋，建議同店同日由一人填寫。支出摘要沿用舊版數字解析：如「消毒3250/菜172」可加總，但日期、數量及含逗號金額可能誤算，請用原有格式「菜1560」輸入。

已移除舊版空月份載入範例資料的邏輯，並處理讀取／刪除錯誤、保留零值顯示及輸入文字 HTML 跳脫。

本次僅交付修改檔案及 SQL，未連線修改正式 Supabase 或部署網站。已通過 JavaScript 語法檢查，並以模擬 DOM 與 Supabase 測試分店隔離、平均、切換儲存、失敗處理與匯出。環境無可用瀏覽器，未完成實際畫面驗證；上線後仍須依上方步驟驗收實際連線。
